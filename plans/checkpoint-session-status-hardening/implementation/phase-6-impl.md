# Implementation Plan: Phase 6 - Watcher Usability and Native Packaging

> Implements [Phase 6](../phases/phase-6.md) of [checkpoint-session-status-hardening](../plan.md)

## Approach

Keep lifecycle reduction, latest-event age calculation, JSONL discovery, and the Phase 5 compact columns intact, and add a presentation-only cutoff constant of exactly `10_800_000` ms. A valid row is old when its already-computed latest physical event age is greater than or equal to that constant. Both live and one-shot output initially omit every old valid row. Live mode alone maintains an in-memory `showOldRows` flag; each lowercase `v` toggles that flag and queues a redraw without modifying rows, logs, lifecycle state, or ordering. When old rows are shown, use four non-empty paragraphs in this order: current `OPEN`/`UNKNOWN`, old `OPEN`/`UNKNOWN`, `CLOSED`, and `ERROR`. Closed rows retain one lifecycle paragraph and newest-first ordering, with old closed rows joining it only while old rows are visible. Error rows have no successfully parsed latest physical event and therefore are not age-qualified or hidden. The public `--stale-ms` and `CHECKPOINT_WATCH_STALE_MS` inputs remain validated compatibility no-ops and do not configure the new fixed cutoff.

Change width allocation so `AGENT` first requests the complete maximum displayed agent identity. At widths that can hold the fixed columns and deterministic minimum flexible cells, reclaim space from `NAME` down to the four-character `NAME` header width before reducing `AGENT`; only genuinely narrow output truncates the agent identity. Treat the existing 120-column default as the explicit ordinary-width acceptance fixture: with `agent="maintainer-direct"` and an oversized session title, the full agent identity must remain byte-for-byte visible, `NAME` must ellipsize first, and every rendered line must remain at most 120 characters. Preserve the total-width cap, ellipsis behavior, compact metrics, `DONE`/`CURRENT`, and closed-current rules.

Add an explicit live-input lifecycle around the existing redraw lifecycle. Only a TTY with raw-mode support becomes interactive. Capture prior input state, install one data listener, recognize each lowercase `v` and raw Ctrl-C, and route Ctrl-C plus `SIGINT`/`SIGTERM` through the same idempotent shutdown. A single `finally`-driven cleanup removes input and signal listeners, restores the prior raw-mode/flow state, closes the watcher, clears the timer, drains queued rendering, and restores the cursor after normal return or any setup/render/watch failure. `--once` and non-TTY input never enter raw mode or install a key listener. Keep the dependency-injection boundary narrow enough for deterministic fake-stream/signal tests and scriptc exact-record compilation. In addition to those Node-level tests, prove the produced native executable's actual live path in a bounded disposable PTY: observe the initial view, create a log and observe filesystem-triggered refresh, send lowercase `v` and observe the old-row paragraph toggle, then send raw Ctrl-C and verify process exit, terminal-input restoration, listener/resource cleanup as externally observable, and final cursor-show output.

Make the ordinary dependency-free ESM source scriptc-compatible without adding scriptc as a package dependency or replacing the Node bin. First stop flowing the index-signature shape of full `process.env` into the narrow watcher environment type: construct and pass an exact record containing only `CHECKPOINT_WATCH_REFRESH_MS` and `CHECKPOINT_WATCH_STALE_MS`. Treat removal of that `SC2002` diagnostic as the first correction, not proof that compilation is complete. On the current 0.0.21 toolchain the next executed `--help` fence is `SC2020` at `positiveInteger` for `Number`/numeric coercion, and coverage also reports later deferred sites in argument assignment, width calculation, optional watcher cleanup, and exact optional I/O shapes. After every bounded source correction, rerun staged `scriptc coverage`, build an exact-name executable, and execute `--help`, `--once`, non-TTY live refresh/shutdown, and the PTY live-input smoke. Apply only the smallest watcher-local rewrites needed to preserve the existing Node argument validation, width, render, and cleanup behavior on those paths; change `src/index.js` only if an executed staged diagnostic proves a scope-consistent imported-core defect. A successful `coverage` or `build` exit alone is insufficient because scriptc may emit runtime-deferred fences. Coverage may continue to report genuinely unreachable imported-core sites; do not demand an unrelated 100% report. Do not use `--dynamic`, annotations/dialects, generated sources, new package dependencies, or broader core-contract refactors. If passing the four native execution paths would require one of those excluded changes, stop before native installer selection and return to the primary instead of widening scope.

Validate the unchanged `bin/` → `../src/` import graph with the iterative coverage/build loop and the ordinary `scriptc build` JavaScript/ESM path. Every real build runs from a disposable tree containing only staged `bin/checkpoint-watch.js` and `src/index.js`; the executable, compiler translation units, `.scriptc`, LLVM, coverage output, and PTY workspace remain below that disposable tree and are removed afterward.

During global installation only, treat scriptc as opportunistic. After the portable watcher source/core are installed but before status-capable OpenCode runtime/plugin assets, detect an executable `scriptc`, stage the two source files, run coverage and build, require an executable output, and smoke its `--help` and `--once` paths from a disposable workspace. Before selecting the binary as the preferred no-argument launch, also run a bounded dependency-free non-TTY native live smoke inside that stage: observe an initial dashboard frame, append a valid fresh log and observe filesystem-triggered refresh, deliver `SIGTERM`, require a clean exit, and require cursor restoration. The full TTY `v`/raw-Ctrl-C/input-restoration proof remains a real-scriptc release/final-gate smoke through the focused Python standard-library PTY helper; it is not a new end-user installer dependency. Only after the installer-safe live smoke passes copy to a same-directory temporary file, set executable permissions, and rename it atomically to `$HOME/.local/bin/checkpoint-watch`. Preserve a user-managed symlink at that destination. Absence, coverage/build failure, or any smoke failure produces concise fallback guidance but returns success from the optional branch, leaves any previous destination untouched, and allows the normal installation to continue. A successfully installed native binary becomes the global printed launch command and the exact Node command remains printed as fallback; failed/absent native installation and every `--project` run print the Node launch command. Project mode must not inspect, create, replace, or otherwise mutate `$HOME/.local/bin`.

## Implementation Steps

### Step 1: Add the fixed old-row view model and deterministic paragraphs

- **What**: Introduce one internal `OLD_ROW_MS = 10_800_000` constant and classify successfully parsed rows from the existing `ageMs` as old exactly when `ageMs >= OLD_ROW_MS`. Keep loading and sorting the complete row set. Build the rendered view from `showOldRows`: omit all old valid rows when false; when true, render current unclosed, old unclosed, closed, and error paragraphs in that order with one blank line only between adjacent non-empty paragraphs. Preserve newest-first `activityMs` ordering and session-ID tie breaks inside each paragraph. Old closed rows are hidden by default and rejoin the single closed paragraph when visible; `ERROR` rows remain visible because no valid latest event age exists. Do not add labels, pseudo-rows, persisted preference, or an age-derived lifecycle value. Keep the old `staleMs` option out of classification.
- **Where**: `packages/checkpoint-core/bin/checkpoint-watch.js` (`OLD_ROW_MS`, `loadSessionRows` row age, view classification/grouping, `formatDashboard`, `render`); `packages/checkpoint-core/test/checkpoint-watch.test.js`.
- **Authorized By**: Phase 6 Includes items 2–3; Acceptance Criteria 2–3; plan decisions that old means latest physical event age `>= 10_800_000` ms, old rows are hidden initially, and age never changes lifecycle state.
- **Why**: Historical rows stop dominating the default dashboard while exact physical-event age and explicit lifecycle remain separate, testable concepts.
- **Considerations**: Test `10_799_999` versus `10_800_000` exactly with a fixed clock; status-only and reopened rows use `latestEvent` just like current age display. A row can cross the boundary on a later timed redraw and should then hide unless old visibility is enabled. Default filtering applies equally to live and `--once`; only live mode can change the in-memory flag. Empty paragraphs produce no extra blank lines. Retain “No direct … sessions found” only when discovery returned no rows; if valid rows exist but all are hidden, render the header with no data rows rather than making a false no-files claim or adding an ungated label.

### Step 2: Prioritize complete agent identity in adaptive widths

- **What**: Replace the fixed eight-character `AGENT` allocation with a desired width derived from the header and complete displayed agent values. Reserve that desired width before allocating ordinary flexible width, and satisfy any width deficit by shrinking `NAME` first, down to the exact four-character `NAME` header width, before truncating `AGENT`; retain bounded deterministic fallback for genuinely narrow terminals and preserve the existing fixed metric/state/context fields. Continue allocating useful residual width to `DONE` and `CURRENT` without allowing any line to exceed the requested terminal width. Pin 120 columns—the current default—as the ordinary-width contract: a row with `agent="maintainer-direct"` and an oversized `NAME` must contain the complete `maintainer-direct` bytes, must ellipsize `NAME` before `AGENT`, and must keep every line at or below 120 characters.
- **Where**: `packages/checkpoint-core/bin/checkpoint-watch.js` (`contentWidth`, width allocation helper replacing/refining `distributedWidths`, `formatDashboard` specs); `packages/checkpoint-core/test/checkpoint-watch.test.js`.
- **Authorized By**: Phase 6 Includes item 1; Acceptance Criterion 1; plan user decision to show complete agent identity at ordinary widths and reclaim title/name space first.
- **Why**: Agent identity is operationally more important than a long mutable session title and currently truncates at eight characters even when `NAME` consumes available flexible space.
- **Considerations**: Keep the explicit 120-column `maintainer-direct`/long-title fixture alongside a genuinely narrow fixture at the exact point where a four-character `NAME` can no longer coexist with the desired agent width; assert that only the latter truncates `AGENT`. Additional current persona values may be table-driven, but an arbitrarily wide-only test cannot satisfy acceptance. Retain deterministic ellipsis, headers, and hard line bounds. Status-only/error `-` values and unusually long identities must not cause negative widths or unbounded lines.

### Step 3: Add lowercase live toggling with total input and terminal cleanup

- **What**: Add a narrow, injectable live-control boundary for stdin and signal registration. In live mode, initialize `showOldRows=false`; on a TTY with `setRawMode`, record prior raw/flow state, enable raw mode, resume only when needed, and register one data listener. Process every lowercase `v` byte as the sole visibility toggle and queue a refresh through the existing serialized render promise. Ignore uppercase `V` and unrelated input. Treat raw Ctrl-C (`\u0003`) and process `SIGINT`/`SIGTERM` as the same idempotent finish request. In one cleanup path, remove only listeners installed by this run, restore prior raw mode, restore/pause input only if this run changed flow, remove both signal handlers, clear the interval, close the directory watcher, await queued rendering, and restore the cursor. Ensure cleanup runs if raw-mode setup, initial render, timer/watch creation, later refresh, or the wait path throws. Keep deterministic Node tests at the injectable boundary, and add a separate real-native PTY driver with fixed 120-column window size and bounded reads/timeouts. Run the child with a deliberately long refresh interval so a promptly observed marker cannot come from the timer. The PTY driver must precreate current and >=3h-old valid rows, verify the old row is initially absent, allow watcher setup after the initial frame, create a fresh marker log and wait for a subsequent complete frame proving filesystem refresh, send `v` and verify the next complete frame contains the old unclosed row after a blank paragraph separator without state/order changes, send `v` again and verify the next complete frame hides it, then send raw Ctrl-C and assert zero exit, pre-run termios/raw flags restored on the slave, and final cursor-show bytes.
- **Where**: `packages/checkpoint-core/bin/checkpoint-watch.js` (`WatchIO` exact shape, live input/signal helper(s), `render`, `runLiveDashboard`, `main` once/live branch); `packages/checkpoint-core/test/checkpoint-watch.test.js`; new `packages/checkpoint-core/test/native-checkpoint-watch-smoke.py` invoked as `python3 .../native-checkpoint-watch-smoke.py <exact-native-binary> <disposable-workspace>`, with the helper running isolated non-TTY and PTY subcases below that workspace.
- **Authorized By**: Phase 6 Includes items 3–4; Acceptance Criteria 3–4; Non-Functional Requirement that keyboard handling restore input mode and cursor state on normal, signal, and failure exits.
- **Why**: Raw terminal input is required for immediate `v` handling, but leaking raw mode, listeners, timers, watchers, or a hidden cursor would make an optional dashboard unsafe to run.
- **Considerations**: `--once` must not read stdin, install listeners, emit ANSI, or enter raw mode. Non-TTY live mode remains signal-driven and safe. Preserve a stream that was already raw or flowing rather than assuming a default. Coalesce through the current promise chain so repeated key/timer/watch refreshes do not overlap. Cleanup must be idempotent when a key/signal finish races a failure or an injected `waitForExit` test. The PTY helper must kill/reap the child and restore/close its own descriptors on every assertion failure or timeout; it supplements rather than replaces deterministic fake-stream failure injection. Do not add alternate keys, persistence, scrolling, or a TUI dependency.

### Step 4: Remove the scriptc environment-shape blocker and verify the staged ESM graph

- **What**: Add a small exact-shape environment reader returning only `CHECKPOINT_WATCH_REFRESH_MS` and `CHECKPOINT_WATCH_STALE_MS`, and use it for `parseArgs` defaults and `main` when no injected exact environment is supplied. Never pass the index-signature object `process.env` directly to the narrow declared type. Keep option precedence/validation and the stale compatibility no-op unchanged. Exercise scriptc only against a disposable copy with `bin/checkpoint-watch.js` beside `src/index.js`. First run ordinary `scriptc coverage` and remove the known full-environment `SC2002`; then rerun coverage and an exact-name build instead of assuming that narrowing completed compatibility. Record and resolve each subsequent diagnostic that is reachable from the required native paths. The current next reproduced blocker is `SC2020` in `positiveInteger` for `Number`/numeric coercion after `SC2002` is removed; current coverage also identifies deferred dynamic option-key assignment, `Math.max` width calculation, optional watcher close, and exact optional I/O/Promise shapes that must be classified by actual `--help`, `--once`, non-TTY live, and PTY live execution. For each reachable fence, make a bounded watcher-local rewrite that preserves Node-visible validation/output/cleanup behavior, rerun focused Node tests, rerun coverage/build, and execute all four paths before moving on. A zero coverage/build status is evidence collection, not success, because runtime-deferred fences may remain. Retain genuinely unreachable imported-core diagnostics as documented non-blocking coverage only; do not broaden work merely to reach 100%. Build to an explicit staged `checkpoint-watch` with generated translation-unit retention disabled, then require native `--help`, `--once`, the installer-safe non-TTY live refresh/signal smoke, and the PTY filesystem/`v`/raw-Ctrl-C cleanup smoke. Do not opt into `--dynamic`, add annotations/dialects, alter the mixed-log core contract, or add generated files/package dependencies. Stop before Step 5 and report a blocker if the four paths cannot pass within those bounded rewrites.
- **Where**: `packages/checkpoint-core/bin/checkpoint-watch.js` (`WatchIO.env`, environment reader, `positiveInteger`, `parseArgs`, width allocation/`contentWidth`, `render`, `runLiveDashboard`, `main`, scriptc main guard); `packages/checkpoint-core/test/checkpoint-watch.test.js`; new `packages/checkpoint-core/test/native-checkpoint-watch-smoke.py`; preserve `packages/checkpoint-core/package.json` and `packages/checkpoint-core/src/index.js` unless an executed staged diagnostic proves a scope-consistent source correction.
- **Authorized By**: Phase 6 Includes item 5; Acceptance Criterion 5; Non-Functional Requirement that native compilation use a disposable staging directory; authoritative fact that full `process.env` produces the first `SC2002` mismatch and accepted review finding F-1 requiring subsequent native diagnostics to remain execution-gating.
- **Why**: scriptc uses exact record shapes and cannot safely width-coerce Node's arbitrary environment map into the watcher's two-key configuration shape.
- **Considerations**: scriptc is optional, locally present as 0.0.21, and experimental. Its compiler requires Node >=20 and clang; produced binaries do not require Node. The documented primary platform is macOS arm64, with Linux/Windows support carrying documented cross-compilation and surface limits, so passing on one host must not be represented as universal support. Keep the Node shebang/bin path authoritative and preserve Node/native argument, stdout, stderr, and exit behavior for `--help`, `--once`, and live mode. The Python PTY helper is test-only and uses only the standard library already required by the broad repository gate; do not make it an installed runtime or native installer prerequisite.

### Step 5: Add optional global native installation without weakening the Node path

- **What**: Add a self-contained installer function invoked only when `PROJECT_MODE=false`, after watcher source/core installation and before OpenCode runtime/plugin installation. If `command -v scriptc` succeeds, create a `mktemp -d` stage under `${TMPDIR:-/tmp}`, create only `bin/`, `src/`, and disposable once/live workspaces, copy the checked-in watcher/core to the matching relative paths, capture the Step 4 coverage report, reject the known `SC2002` and `SC2020` numeric-coercion fences even if coverage exits zero, then build and run installer-safe `--help`, `--once`, and non-TTY no-argument live paths. Start the live child with non-TTY stdin and a deliberately long refresh interval, bound every wait/poll, observe the initial dashboard, allow watcher setup, append a valid marker log inside the watched directory, require a prompt subsequent frame containing that marker before the timer could fire, send `SIGTERM`, wait for zero exit, and require final cursor-show bytes; failure at any point rejects native preference. The PTY `v`/raw-mode smoke remains in focused/final verification so the installer gains no Python dependency. Guard every optional command explicitly so `set -euo pipefail` cannot abort the normal installer. On verified success, create `$HOME/.local/bin` if needed, refuse to overwrite a symlinked `checkpoint-watch`, copy the binary to a same-directory temporary ordinary file, set executable mode, and `mv` it over the regular destination as the atomic commit. Clean the build tree and any child process on every outcome. Track success for summary output: native success prints the native path as `Launch command` and the exact installed Node invocation as `Node fallback`; all other cases print the Node invocation as `Launch command` plus a concise reason/guidance. Never install scriptc, modify `PATH`, remove the portable watcher source, or treat optional failure as installation failure.
- **Where**: `install.sh` (new optional native build/install helper, call inside `install_opencode_checkpoint` between reader and writer copies, cleanup, project guard, summary launch selection); `opencode/test/checkpoint-plugin.test.mjs` installer helpers and global/project scenarios.
- **Authorized By**: Phase 6 Includes items 6–7; Acceptance Criteria 6–7; plan decision that global installation may atomically install `$HOME/.local/bin/checkpoint-watch` when scriptc is usable while project mode and normal Node installation remain independent.
- **Why**: Users with a working compiler get a verified direct executable, while every supported installation retains the dependency-free source and exact Node escape hatch.
- **Considerations**: Fake scriptc/native fixtures must cover absent CLI, coverage failure, build failure, non-executable output, failed `--help`, failed `--once`, live-start failure, missing filesystem refresh, live signal/exit failure, missing cursor restoration, and full success without relying on the author's real installation. Every failure leaves a pre-existing destination byte-for-byte unchanged and still installs/runs the Node watcher. Success replaces a regular prior binary only after all installer-safe smokes pass and yields executable bytes. Confirm the scriptc working directory/input/output paths are outside the repository and no `.scriptc`, `.ll`, `.c`, or compiler cache appears in the checkout. In project mode, pre-create a sentinel at the global destination and prove its bytes/metadata and parent contents are unchanged; do not even probe scriptc there. Preserve reader-first output order and existing required-reader symlink preflight.

- **What**: Update user-facing and inventory documentation for the exact fixed cutoff, hidden-by-default behavior in both modes, lowercase live-only toggle, old-unclosed paragraph, unchanged lifecycle meaning, the explicit 120-column full-agent priority, raw-mode cleanup, and stale-option non-relationship. Document that Node source remains installed and authoritative; global installs opportunistically stage/iteratively diagnose/build/smoke and atomically install a native binary only when scriptc and its no-argument live path are usable; project installs never touch the global bin; and the printed launch/fallback commands are the source of truth. Qualify prior “no compilation step” statements as “no required compilation step.” State scriptc's optional experimental status, runtime-deferred diagnostic behavior, Node >=20 compiler prerequisite, clang/toolchain need, and platform limits without promising installer portability beyond successful local build/smoke evidence. Update behavior-bearing documentation assertions along with the implementation tests.
- **Where**: `README.md`; `docs/overview.md`; `docs/installation.md`; `docs/agent-checkpoint-heartbeat.md`; `docs/modules/checkpoint-core.md`; `docs/modules/opencode-checkpoint-adapter.md`; `docs/modules/installation-and-configuration.md`; documentation assertions in `opencode/test/checkpoint-plugin.test.mjs`.
- **Authorized By**: Phase 6 Includes item 8; Deliverable “Optional global native installation with Node fallback and documentation”; Acceptance Criteria 1–7; global DoD requiring current docs to match final code and honest limitations.
- **Why**: Current docs say there is no build step, show only a Node launch, divide flexible space equally, show all rows, and mention only timer/watcher/cursor cleanup; those claims become incomplete after Phase 6.
- **Considerations**: Do not rewrite lifecycle schemas, adapter identity/closure docs, inspector behavior, activation policy, or the existing pinned Claude/Hermes blocker. Keep exact Node commands available even when native installation succeeds. Do not describe an old row as stale, dead, closed, inactive, or failed.

### Mismatches / Notes

- `DEFAULT_STALE_MS`, `--stale-ms`, and `CHECKPOINT_WATCH_STALE_MS` still exist but Phase 5 deliberately made them validated output-neutral compatibility inputs. The new three-hour cutoff must be a separate fixed presentation rule, not a semantic revival of those inputs.
- Current `formatDashboard` fixes `AGENT` at eight characters and gives `NAME`, `DONE`, and `CURRENT` equal residual shares, so complete identities can be truncated while mutable titles retain space. The gated priority requires an allocator change, not merely a larger fixed constant.
- The current formatter defaults to 120 columns. That exact width, `maintainer-direct`, an oversized `NAME`, and a four-character `NAME` minimum now define the ordinary-width acceptance fixture; wider-only evidence is insufficient, while narrower behavior remains deterministic fallback.
- Current live cleanup covers interval, watcher, queued rendering, and cursor. It neither configures stdin nor restores raw/flow state, and its default signal listeners are removed only by their own finish callback; Phase 6 needs one ownership-aware cleanup path before adding keyboard input.
- A staged local scriptc 0.0.21 coverage probe identifies `SC2002` where the full index-signature `process.env` flows into the declared exact two-key watcher environment shape. Execution must construct the narrow record explicitly; widening the declared type would evade rather than solve scriptc's exact-shape constraint. A second staged probe with equivalent exact environment narrowing removes `SC2002` but the exact-name native `--help` then reaches `SC2020` at `positiveInteger` for `Number`/numeric coercion. The same report identifies later deferred argument-key, `Math.max`, watcher-close, and optional-I/O/Promise sites. These are diagnostics to classify against the required four native paths, not proof that every imported unreachable site must be rewritten; `coverage`/`build` success alone is not acceptance.
- The current native plan's former `--help`/`--once` pair did not execute `runLiveDashboard`, even though successful global installation prints the native no-argument live command. Phase 6 now requires a bounded installer-safe non-TTY refresh/signal smoke plus a real 120-column PTY smoke that exercises filesystem refresh, `v` show/hide, raw Ctrl-C, termios restoration, timeout cleanup, and cursor-show output.
- `install.sh` currently claims no external dependencies beyond shell/core tools and always prints the installed Node source as `Launch command`. The truthful post-phase statement is that installation has no required new dependency: scriptc is optional, and only a verified global build changes the preferred launch for that run.
- `docs/overview.md` and the checkpoint module currently say there is no build step. Node installation still requires none, but a global installer may now perform an optional disposable native build, so the wording must become “no required build step.”
- scriptc is installed on the authoring host as 0.0.21, but it must not become a pinned package/runtime dependency or be assumed on user hosts. The broad portion of the single final command continues to fail clearly at those two checks here until run in a suitable environment; Phase 6 must not waive, skip, or misreport that independent blocker.
